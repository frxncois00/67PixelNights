IMPLEMENTED SYSTEMS
1. Crafting
- ScriptableObject recipes reference existing ItemDefinition assets and stable item IDs.
- Wooden Fence: 3 wood, output 1; stack 20.
- Reinforced Barricade: 5 wood + 2 stone, output 1; stack 20.
- Storage Chest: 6 wood + 2 scrap, output 1; stack 10.
- Repair Kit: 2 wood + 1 scrap, output 1; stack 20.
- CraftBatch simulates all ingredients and output insertion before committing. Smaller ingredient stacks are consumed first to free output slots. One inventory Changed event is emitted per successful recipe.
- Insufficient ingredients or output space spends nothing. Rapid duplicate craft requests are throttled.
- Workbench uses the existing contextual E interaction list, configurable range 2. No independent E listener was added.
- UI lists recipes, icons, owned/required material counts and craft availability.

2. Placement
- Equip a crafted building item in hotbar; B toggles placement; left click places; right click or Escape cancels.
- Maximum range defaults to 3; half-unit position snapping.
- Green/red translucent sprite plus footprint outline. Ghost has no Collider2D.
- Preview validation is limited to four checks per second while following the pointer. Click always revalidates the current position synchronously before spending.
- Rejects water/unsupported footprint, solid overlap/player overlap, excessive range, blocked main cross paths, essential interaction proximity and failed simulated routes.
- Simulated footprint checks player-to-camp connection, camp-to-region routes and enemy/sheep escape connectivity. It fails closed if the bounded region checks time out.
- Placement requires the selected owned building item, consumes exactly one, and invalidates navigation.
- Build mode and crafting/storage modals block world gathering/weapon/food/drop input through existing interaction gates. Building mode still permits movement; modals stop player movement.

3. Structures
- Fence 50 HP; reinforced barricade 150 HP; chest 50 HP.
- Static BoxCollider2D footprints; unit GameObject scale; Objects sorting layer and pivot sort point.
- Damage API with brief white flash and selected-structure health bar/text.
- Repair restores up to 25 HP for one repair kit; full health spends none.
- E opens management. Dismantle requires two clicks; no refunds. Nonempty storage cannot be dismantled.
- Enemy structure attacks are NOT implemented (optional). Enemies use the existing navigation/physical obstacles and do not gain a new damage authority.

4. Storage
- Twelve independent chest slots; player inventory remains InventoryController.
- Select a source slot, then deposit/withdraw one or stack.
- Partial transfer accepts only destination capacity; no overflow deletion.
- Destroyed nonempty chest becomes a nonblocking, withdraw-only wreck. Contents remain recoverable through E; no requirement for free ground drop space and no silent deletion.
- Chest destruction currently requires the structure damage API/test; there is no new enemy/player attack targeting of structures.
- Session-only structures and storage; no persistent save system was requested or added.
